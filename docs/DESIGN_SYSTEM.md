# Admin Design System

> 이 문서는 구현의 단일 기준입니다. 어드민의 `디자인 시스템` 페이지는 이 문서의 시각화이며, 규칙을 변경할 때 문서·페이지·구현을 같은 변경 단위로 갱신합니다.

## 어드민 테마와 프론트 가이드 연결

- 테마 카드의 `디자인 시스템 보기`는 보조 안내가 아니라 실제 링크입니다. 각 카드는 자신의 프론트 디자인 시스템 파일만 열며 새 탭을 사용해 편집 중인 어드민 상태를 보존합니다.
- 링크 매핑은 `Mist → /front-system.html`, 그 외 테마는 `{Theme} → /front-system-{theme}.html` 규칙을 사용합니다.
- 가이드 안의 공통 헤더에서 다른 테마로 이동할 수 있지만, 처음 열린 문서와 활성 표시는 반드시 클릭한 테마와 일치해야 합니다.
- 어드민 자체 디자인 시스템과 프론트 테마 디자인 시스템은 별도 문서입니다. 테마 카드 링크가 `#admin-system`을 열어서는 안 됩니다.

## 구현 동기화 규칙

- 실제 어드민에서는 `설정 → 디자인 시스템`으로 언제든 이 가이드를 열 수 있어야 합니다.
- 구현 중 기존 카탈로그로 설명할 수 없는 패턴이 생기면 화면별 예외 CSS를 먼저 만들지 않습니다. 컴포넌트 이름, 용도, variants, states, 반응형 동작과 데이터 안전 조건을 이 문서와 시각 카탈로그에 먼저 추가한 뒤 실제 화면에 사용합니다.
- 라이브 어드민과 가이드의 토큰 값은 같아야 하며, 라이트·다크 양쪽에서 같은 의미 역할을 유지합니다.
- 실제 어드민의 공통 셸, 페이지 헤더, 액션 바, 폼, 오버레이와 목록은 `src/index.css`의 `Admin implementation contract` 블록을 공통 계약으로 사용합니다.
- 시각 가이드는 실제 동작을 대체하지 않습니다. `#admin-system`에는 명세와 실제 형태를, `#admin`에는 운영 가능한 컴포넌트를 둡니다.

## 정보 구조

- Overview: Dashboard → Save status → Recent changes → Operational alerts
- Content: Site sections → Projects (structured · archive) → Taxonomy → Bulk JSON
- Governance: Access tokens → Session journey → Access logs → Behavior analysis → Backup & restore → Theme → Design system
- 목록에서 상세 화면으로 이동한 뒤 돌아오면 필터, 정렬과 스크롤 위치를 보존합니다.
- 버튼이나 링크처럼 보이는 요소는 실제 운영 행동이나 목적지가 있을 때만 표시합니다.
- 공개 포트폴리오의 브랜드·편집 디자인 규칙은 이 문서와 어드민 컴포넌트의 범위에 포함하지 않습니다.

## UX 전역 규칙

- 정렬: 모든 섹션은 공통 콘텐츠 시작선과 번호 열을 사용합니다.
- 정보 위계: 페이지 제목과 첫 패널 제목이 같은 대상을 가리키면 패널 제목을 반복하지 않고, 바로 하위 편집 그룹이나 데이터 목록을 시작합니다. 한 페이지에 병렬 패널이 둘 이상이면 각 패널의 서로 다른 작업 범위를 서브 제목으로 표시합니다. 단일 패널은 페이지보다 좁은 별도 범위를 정의할 때만 제목을 사용합니다.
- 범위 선택: 상위 선택이 아래 작업 범위를 바꾸면 활성 항목에 ‘현재 편집 중’을 표시하고, 선택기와 공통 액션 바를 하나의 연결된 작업 묶음으로 표현합니다. 선택 컨트롤은 `aria-controls`로 영향을 받는 편집 영역과 연결합니다.
- 폭: 같은 편집 맥락의 페이지 헤더, 액션 바, 안내 바, 폼 패널과 목록은 같은 좌우 컨테이너 선을 사용합니다. 읽기 폭을 제한해야 하면 액션 바를 포함한 작업 묶음 전체를 함께 제한하며, 폼만 임의의 `max-width`로 줄이지 않습니다.
- 줄바꿈: 넓은 화면의 안내 문장은 사용 가능한 폭을 쓰며 임의 max-width 때문에 한두 글자만 다음 줄로 보내지 않습니다. 화면이 좁을 때만 단어 단위로 자연스럽게 줄바꿈합니다.
- 간격: 8px 배수 토큰을 사용하며 경계선과 내용 사이 상하 패딩을 동일하게 둡니다.
- 상태: hover, focus, pressed는 색과 선으로 표현하고 요소의 위치·크기를 바꾸지 않습니다.
- 깊이: 일반 버튼·카드·액션 바에는 그림자나 발광을 사용하지 않습니다. 화면 위에 뜨는 Dialog, Drawer, Toast, Tooltip처럼 레이어 분리가 필요한 요소에만 제한적으로 사용합니다.
- 콘텐츠: 원본 데이터와 순서를 보존하며 값이 없을 때만 항목을 숨깁니다.
- 반응형 변경은 모바일 360/390, 태블릿 768/1024, 데스크톱 1280/1440에서 검증합니다.
- 내용보다 높은 셀·카드·표본 영역은 콘텐츠 묶음을 수직 중앙에 배치합니다. 제목과 설명은 각각이 아니라 묶음 전체의 시각 중심을 기준으로 정렬합니다.
- 아이콘과 글자는 수학적 박스 중앙이 아니라 기준선과 시각 무게를 맞춥니다. 아이콘 보정은 1px 이내이며 같은 컴포넌트에서 동일해야 합니다.

## 타이포그래피

- 페이지 제목은 데스크톱 32/40px, 모바일 28/36px, 어드민 섹션 헤더는 18/28px, 컴포넌트 제목은 16/24px, 본문과 표 주요 값은 16/26px을 사용합니다.
- 일반 입력값·버튼은 15/22px, 공간이 제한된 보조 툴바와 compact 버튼은 14/22px을 사용합니다.
- 필드 라벨·보조 설명은 14/22px, 번호·코드·그래프 축·기술 주석만 13/20px을 사용합니다. 렌더링되는 어드민 글자는 어떤 경우에도 13px 미만으로 줄이지 않습니다.
- 같은 역할은 같은 크기를 사용합니다. 글자가 넘칠 때는 Micro 단계인 13px까지만 줄이고, 그래도 부족하면 더보기나 다음 행으로 이동합니다.
- 허용하는 본문 계층은 Page 32/40, Section 18/28, Component 16/24, Body 16/26, Control 15/22, Support 14/22, Micro 13/20입니다. 숫자 지표와 시각 표본을 제외하고 임의 크기나 단위 없는 줄높이를 추가하지 않습니다.
- 어드민 섹션 헤더는 편집 화면과 연결된 패널 헤더로 표현합니다. `번호 셀 | 18px 제목 | 14px 설명`을 한 줄에 두며, 포트폴리오처럼 큰 제목과 넓은 여백을 사용하지 않습니다.
- 구조 도식과 토큰 표본은 설명 콘텐츠이므로 항목명 16/24px, 설명 14/22px을 사용합니다. 번호·코드 같은 기술 표기만 13/20px 메타 토큰을 사용합니다.
- 홈 대시보드는 표 편집 화면보다 읽기 비중이 높으므로 패널 제목 16/24px, 지표·행동 라벨 14/22px, 설명·그래프 범례·축 13/20px을 사용합니다. 대시보드 밀도를 이유로 Micro 토큰을 일반 문장에 적용하지 않습니다.
- 순서가 있는 카드의 번호는 별도 24px 열에 두고 제목의 첫 기준선에 맞춥니다. 카드 전체 높이의 중앙이나 제목과 설명 사이에 번호를 두지 않습니다.

## 컴포넌트 카탈로그

- Navigation: Admin shell, Nav item, Section header, Floating jump navigation.
- Actions: Action bar, Primary/Secondary/Quiet/Danger/Icon button, Import/Export, Row actions.
- Form controls: Text, URL, Number, Auto textarea, Select, Year, Date/Datetime/Range, Color picker + HEX, Checkbox/Radio/Switch.
- Editing: Document field group, Collection panel, Summary row, Editor sheet, Repeatable row, Master/Detail, Taxonomy/Tag, Media field, JSON bulk drawer, Theme assignment, Theme preview toolbar.
- Data display: Status strip, Table/List, Filter/Search, Pagination, Chart, Session journey.
- Feedback/Overlay: Inline validation, Toast, Dialog, Drawer, Empty/Loading/Error, Tooltip/Popover.
- 각 컴포넌트는 용도, variants, Default · Hover · Focus · Active · Disabled · Loading · Error를 필요한 컴포넌트마다 정의합니다.
- 카탈로그의 모든 컴포넌트는 실제 구조와 핵심 상태를 축약한 시각 specimen을 명세와 함께 표시합니다.
- 표본 레이아웃은 `compact`와 `full-width`로 구분합니다. 버튼 묶음·선택 컨트롤·페이지네이션·바로가기는 가로·세로 중앙에 두고, 입력·표·툴바·편집기는 가용 폭을 사용합니다.
- 반복 데이터 안에 다시 반복 데이터가 들어가면 아코디언을 중첩하지 않습니다. 상위 레코드는 한 단계만 접고, 내부 컬렉션은 `목록(master) + 선택 항목 편집(detail)` 패턴으로 표시합니다. 한 시점에 한 내부 항목만 편집하며 현재 선택을 선과 배경으로 명확히 구분합니다.
- 편집 패널은 콘텐츠 높이만 사용합니다. 탭 간 높이를 맞추기 위한 임의 `min-height`나 입력 아래의 빈 공간을 두지 않습니다. 하단 이동·삭제 행동은 내용 직후의 동일한 푸터 선에 붙입니다.
- 짧은 반복 항목은 카드 한 장씩 세로로 쌓지 않고 열이 정렬된 compact 편집 표를 사용합니다. 핵심 성과는 `순서 | 제목 | 성과 내용 | 연결 및 관리` 순서이며 모바일에서만 라벨이 있는 세로 행으로 전환합니다.
- 반복 편집 행의 모든 필드는 행의 위쪽 기준선에 맞추고 단일 입력·선택은 42px 높이를 공유합니다. 여러 줄 입력만 내용에 따라 아래로 확장하며, 이 때문에 다른 필드를 행의 수직 중앙으로 내리지 않습니다.
- 삭제·복제·이동 같은 행 관리는 독립된 끝 열로 멀리 떼어 놓지 않습니다. 마지막 관련 필드와 하나의 관리 그룹으로 묶어 8px 간격으로 배치하고, 텍스트 삭제 버튼은 Desktop 42px·Mobile 44px 이상의 조작 높이를 사용합니다.
- 반복 편집 행이 한 열로 전환되면 각 필드 라벨을 복원하고 ‘마지막 필드 | 관리 행동’의 인접 관계를 유지합니다. 삭제 버튼만 번호 옆이나 행 반대쪽 모서리로 이동시키지 않습니다.
- 접힌 요약 행은 회사명·직함·프로젝트 수·기간에 공통 열 토큰을 사용하고, 내용 길이가 달라도 각 열의 시작선이 행마다 움직이지 않습니다.
- 하나의 공개 섹션을 편집하는 문서형 화면은 모든 필드를 전체 폭 한 열로 나열하지 않습니다. 필드를 `식별 정보`, `메인 메시지`, `행동·연락`처럼 의미로 묶고, 짧은 값은 데스크톱 2열·태블릿과 모바일 1열, 여러 줄 카피는 같은 의미의 필드끼리 배치합니다.
- 반복 데이터의 상위 묶음은 `제목·설명·추가 행동` 헤더와 정렬된 본문을 가진 Collection 패널을 사용합니다. 빈 목록은 같은 패널 안에서 원인·다음 행동을 제공하며, 임시 태그 목록과 반복 카드로 같은 정보를 중복하지 않습니다.
- 데스크톱 제어 높이는 기본 40px, compact 36px이며 모바일 터치 제어만 최소 44px을 사용합니다. 아이콘 버튼은 정사각형이고 표 행은 최소 44px입니다.
- 빈 상태는 `initial`, `filtered`, `permission`을 구분합니다. 제목에는 비어 있는 이유, 본문에는 복구 방법, 하단에는 가능한 행동 하나만 두며 권한이 없으면 생성 행동을 노출하지 않습니다.
- 입력·선택 컴포넌트의 focus는 기존 박스 테두리를 2px 강조하며, 브라우저 기본 outline이나 추가 외곽 ring을 겹쳐 표시하지 않습니다.
- 사용자가 의미를 알기 어려운 기술 필드에는 사람이 이해하는 이름, 실제 결과 예시와 자동 생성 행동을 함께 둡니다. 프로젝트 `slug`는 `페이지 주소`로 표기하고 `/projects/{값}` 미리보기를 표시합니다.
- 기간처럼 값의 범위와 단위가 정해진 필드는 자유 텍스트가 아니라 `숫자 선택 + 단위 선택`을 사용합니다. 기존 문자열은 파싱해 같은 의미로 표시하여 데이터 호환성을 유지합니다.
- 경력·경력 프로젝트의 시작/종료 시점은 월 선택기 두 개와 `현재` 체크로 입력합니다. 학력은 시작·종료 연도 드롭다운을 사용합니다. 저장 문자열은 기존 포맷을 유지하여 공개 화면과 JSON 덤프 호환성을 깨지 않습니다.
- 시작·종료·현재를 함께 가진 기간 입력은 복합 컨트롤입니다. 짧은 텍스트 필드와 동일한 3등분 열에 넣지 않고 최소 480px 또는 해당 행 전체 폭을 사용하며, 작업 폭이 부족하면 구성 요소를 자르지 않고 한 열로 전환합니다.
- 미디어 필드는 URL 입력과 로컬 파일 업로드를 함께 제공합니다. 대표 이미지는 2400×1600px, 3:2, WebP/JPEG/PNG/AVIF, 최대 8MB를 기본 가이드로 하며 업로드 전 파일 형식·크기를 검증하고 현재 이미지를 즉시 미리보기합니다.
- 반복 미디어 행은 `번호·제목·가로 행동` 헤더, 이미지 입력, 대체 텍스트·캡션 순서로 배치합니다. 이동 버튼을 세로 열로 쌓거나 본문 입력 사이에 삭제 행동을 끼우지 않습니다.
- 분류 데이터는 `표시 이름 + 안정적인 식별자`만 관리합니다. 분류색은 콘텐츠 데이터에 저장하지 않고 방문자 테마 토큰으로 표현합니다. 레거시 JSON의 색상 키는 호환을 위해 보존하되 렌더링에는 사용하지 않습니다.

## 특수 편집 화면

- 테마 화면은 `진입 화면`과 `기본 방문자` 중 적용 대상을 먼저 고른 뒤 실제 색상 견본·이름·설명이 있는 테마 카드를 선택합니다. 토큰별 테마는 토큰 발급·재발급 화면에서 선택합니다.
- 현재 화면에서 선택할 수 없는 적용 대상은 탭이나 카드처럼 표시하지 않고, 관련 관리 위치를 한 문장으로 알려주는 일반 안내로 구분합니다. 제목과 설명을 나눈 카드형 문법도 사용하지 않습니다.
- 콘텐츠에서 직접 정하는 강조색은 테마별 override로 저장합니다. 기존 단일 `color` 값은 삭제하지 않고 테마별 값이 없을 때의 fallback으로 유지하여 과거 데이터와 JSON 덤프를 보존합니다.
- 적용 우선순위는 토큰별 지정 → 기본 방문자이며, 진입 화면 테마는 인증 전 토큰 입력 화면에만 적용합니다.
- 테마 선택 화면은 적용 대상 선택과 테마 카드 목록을 제공합니다. 테마 자체를 어드민 안에 재현하지 않습니다.
- 테마 적용 대상 버튼을 목록의 유일한 타이틀로 사용하고, 선택 패널 안에서 같은 대상명을 다시 제목으로 반복하지 않습니다.
- 미리보기 진입은 각 테마 카드 하단에만 두며 카드 목록 위에 전체 미리보기 버튼을 중복하지 않습니다.
- 미리보기는 선택한 테마의 실제 포트폴리오 또는 진입 화면을 열고, 독립된 고정 툴바에서 테마·화면·Mobile/Tablet/Desktop 폭을 전환합니다.
- 미리보기 툴바는 방문자 테마가 아니라 저장된 어드민 라이트·다크 모드의 표면·선·글자·강조 토큰을 사용합니다. 이 구분은 화면 안내 문구로 설명하지 않고 시각적 일관성으로만 드러냅니다.
- 미리보기 툴바는 `테마 미리보기` 제목과 `테마 · 화면 · 폭` 라벨을 항상 표시합니다. Desktop·Tablet은 제목 행 아래에 컨트롤을 정렬하고 Mobile은 라벨을 유지한 채 한 열 작업 흐름으로 재배치합니다.
- 폭 전환은 외곽 컨테이너만 줄이지 않고 독립 프레임의 실제 viewport를 390/768/전체 폭으로 바꿉니다. 각 테마의 미디어 쿼리도 선택한 폭을 기준으로 실행되어야 합니다.
- 미리보기 중 변경은 임시이며 저장 데이터를 바꾸지 않습니다. `어드민으로`를 누르면 이전 스크롤과 편집 상태로 돌아갑니다.
- Desktop 툴바는 실제 화면 하단 중앙, Tablet은 최대 두 줄, Mobile은 하단 전체 폭과 safe area를 사용합니다.
- JSON bulk, 이미지 관리, 복원 이력처럼 일반 폼을 벗어나는 화면도 카탈로그의 Drawer/Media/Data safety 규칙을 조합합니다.

## 어드민 운영 규칙

- 저장 상태는 변경됨 → 저장 중 → 저장됨 또는 실패의 네 단계로 표시합니다.
- 저장 실패 시 입력값을 보존하고 원인과 재시도 행동을 같은 위치에 유지합니다.
- 검증 오류는 필드 아래에 표시하며 제출 시 첫 오류로 포커스를 이동합니다.
- 로딩은 실제 레이아웃과 같은 골격을 사용하고, 빈 상태는 원인과 다음 행동을 함께 제공합니다.
- 저장되지 않은 변경이 있을 때만 페이지 이탈 경고를 표시합니다.
- 성공 토스트는 자동 종료하고 오류 메시지는 사용자가 닫을 때까지 유지합니다.
- 브라우저 기본 `alert`, `confirm`, `prompt` 대신 시스템 다이얼로그를 사용합니다.
- 위험 다이얼로그는 취소에 초기 포커스를 두고 대상·영향·복구 가능 여부를 설명합니다. 닫기 버튼은 배경과 3:1 이상 경계를 유지합니다.
- 삭제, 기록 제거, 이미지 비우기와 연결 해제는 데이터가 서버에 이미 저장됐는지와 무관하게 항상 시스템 확인창을 먼저 표시합니다. 편집 중인 값만 제거하는 경우에는 `저장 전까지 실제 데이터에 반영되지 않음`을 명시합니다.
- 삭제 확인 제목에는 대상 종류를, 본문에는 가능한 경우 대상 이름을 표시합니다. 브라우저 기본 확인창이나 즉시 삭제 링크를 사용하지 않습니다.

## 데이터 작업과 보안

- JSON 가져오기는 스키마 검증 → 추가·수정·삭제 차이 미리보기 → 복원 지점 생성 → 적용 순서로 진행합니다.
- 삭제·초기화·복원은 대상 이름, 영향과 복구 가능 여부를 확인한 뒤 실행합니다.
- 전체 삭제는 대상 이름 재입력을 요구합니다.
- 표는 검색, 필터, 정렬, 결과 수와 페이지네이션을 제공하며 임의 개수에서 데이터를 잘라내지 않습니다.
- 접속 로그 기본 페이지 크기는 25건이며 현재 페이지와 전체 페이지 수를 표시합니다. 필터를 바꾸면 첫 페이지로 돌아가고 열린 상세 행을 닫습니다.
- 일괄 행동은 하나 이상의 행이 선택된 뒤에만 표시합니다.
- 토큰은 생성 직후 한 번만 전체 값을 표시하고 이후에는 마스킹합니다.
- 토큰 목록은 카드 묶음이 아니라 `뷰어·토큰 / 접속 범위 / 방문자 테마 / 작업` 열을 가진 운영 레지스터로 표시합니다. 태블릿에서는 두 열 요약, 모바일에서는 라벨이 붙은 한 열 레코드로 전환합니다.
- 토큰의 복사·QR·이력은 즉시 행동으로 유지하고, 재발급·연장·즉시 만료·폐기·영구 삭제는 `관리` 메뉴에 묶습니다. 위험 행동은 일반 행동과 색·확인 단계로 구분합니다.
- 토큰 상태는 색만 쓰지 않고 상태점과 `활성·만료·폐기` 텍스트를 함께 표시합니다. 생성·만료·최근 접속은 줄바꿈 문장이 아니라 동일한 키/값 열로 정렬합니다.
- 토큰 접속 추이는 토큰 목록 위의 고정된 통계 영역에서 유지합니다. 기록이 0건이어도 영역을 숨기지 않되, 빈 축과 범례를 함께 그리지 않고 차트 프레임 중앙의 단일 빈 상태로 대체합니다. 7·14·30일은 일 단위, 90일은 주 단위로 자동 집계합니다.
- 시간은 ISO/UTC로 저장하고 화면에는 KST 절대 시간과 상대 시간을 함께 표시합니다.
- 복원 이력에는 누가, 언제, 무엇을 변경했는지 기록합니다.

## 통계 시각화

- 막대는 항목 비교, 선은 시간 추세, 100% 누적은 구성비, 큰 숫자는 단일 핵심 지표에 사용합니다.
- 기본 계열 한 색과 강조색 한 색을 사용하며 의미 없는 무지개색을 사용하지 않습니다.
- 축은 0 기준을 유지하고 격자는 최대 4개, 숫자 정밀도와 단위를 통일합니다.
- hover, 키보드 focus와 모바일 tap에서 항목·값·단위·기간을 툴팁으로 표시합니다.
- 그래프는 색상 외 라벨과 텍스트 요약을 제공하며 로딩·빈 값·오류 상태를 각각 정의합니다.
- 모바일 그래프는 높이 180px을 기준으로 X축 라벨과 표시 항목 수를 축약합니다.

### 시계열 기간과 집계

- 그래프 필터는 빠른 기간 `7일 · 30일 · 90일 · 1년 · 전체`, 시작일·종료일 달력 필드, 집계 단위 선택, 이전 기간 비교와 적용 버튼을 한 영역에 배치합니다.
- 프리셋 선택 시 날짜 범위와 권장 집계 단위를 함께 갱신합니다. 직접 선택은 시작일 다음 종료일 순서이며, 종료일이 시작일보다 빠르면 종료일 필드 아래에 오류를 표시하고 적용을 차단합니다.
- 필터 변경만으로 그래프를 즉시 바꾸지 않습니다. `적용` 전에는 현재 그래프를 유지해 여러 조건을 한 번에 확정할 수 있게 합니다.
- 기본 조회 범위는 최근 30일이며 7일, 30일, 90일, 1년과 전체 범위를 직접 선택할 수 있습니다.
- 1–31일은 일 단위, 32–180일은 주 단위, 181일–2년은 월 단위, 2년 초과는 분기 단위로 자동 집계합니다.
- 한 그래프의 데이터 포인트는 일 31개, 주 26개, 월 24개를 기본 상한으로 하며 2년 초과 범위는 최대 40개 분기로 표시합니다.
- 상한을 넘으면 원본 날짜를 버리거나 숨기지 않고 다음 집계 단위로 올립니다. 전체 원본은 표 또는 내보내기로 확인할 수 있어야 합니다.
- X축 날짜 라벨은 Desktop 8개, Tablet 6개, Mobile 4개 이하로 제한하되 시작일과 종료일은 항상 표시합니다.
- 주 집계는 KST 월요일 시작을 기준으로 하며, 월 경계의 불완전한 주와 현재 진행 중인 월은 `부분 기간`으로 표시합니다.
- 집계된 점의 툴팁에는 시작일–종료일, 합계 또는 평균, 단위와 집계 방식을 표시합니다.
- 기록이 없는 날짜는 0으로 치환하지 않고 선을 끊거나 `데이터 없음` 상태로 표시합니다.
- 이전 기간 비교는 현재 선택 범위와 같은 일수로 맞추며 시간대는 화면과 내보내기 모두 KST를 기본으로 표시합니다.

## 접속 로그 여정과 분석

- 접속 로그는 원본 시간순 목록과 함께 세션 단위 단계 다이어그램을 제공합니다.
- 단계에는 순서, 행동명, 발생 시각, 다음 단계까지의 시간과 핵심 상태를 표시합니다.
- 주요 전환, 장기 체류와 이탈 지점은 색상뿐 아니라 라벨로 구분합니다.
- 모바일에서는 단계를 세로 타임라인으로 전환하며 순서와 시간 정보를 유지합니다.
- 분석 코멘트는 관찰된 사실, 해석, 신뢰도와 권장 확인 사항을 분리합니다.
- 표본 수, 반복 행동과 체류 시간을 근거로 신뢰도를 낮음·중간·높음으로 표시합니다.
- 접속 로그만으로 방문자의 감정, 성향이나 의사결정을 확정하지 않습니다.
- 코멘트마다 추가로 확인할 데이터 또는 실행 가능한 개선 행동을 연결합니다.

## 접근성·레이어·모션

- 일반 텍스트는 4.5:1, 큰 텍스트와 UI 경계는 3:1 이상의 대비를 유지합니다.
- primary·secondary·quiet·danger·icon·link 버튼은 각각 default, hover, focus, pressed, disabled, loading의 배경·글자·테두리를 한 세트로 정의합니다. hover에서 글자색만 연하게 만들거나 primary의 채움만 제거하지 않습니다.
- Light와 Dark 모두 primary 라벨 4.5:1, 아이콘과 컨트롤 경계 3:1 이상을 유지합니다. hover와 pressed에서도 같은 기준을 다시 측정합니다.
- hover는 색·표면·선으로만 피드백하고 위치 이동, 확대, padding 변화와 레이아웃 재배치를 만들지 않습니다.
- 다이얼로그는 포커스를 가두고 Esc로 닫히며, 닫은 뒤 원래 트리거로 포커스를 돌려보냅니다.
- 오버레이 베일은 라이트 14%, 다크 24%의 중성색만 사용합니다. 배경 행동을 비활성화하되 버튼과 페이지 구조가 사라진 것처럼 보일 정도로 탁하게 덮지 않습니다.
- 버튼·행·입력의 터치 영역은 최소 44px입니다.
- 사용자 데이터는 스타일 때문에 임의로 자르지 않으며 긴 URL과 토큰에는 줄바꿈과 복사 기능을 제공합니다.
- 레이어는 Canvas 0, Sticky 10, Dropdown 20, Overlay 30, Dialog 40, Toast 50을 사용합니다.
- 플로팅 바로가기와 맨 위 이동은 44×44px 정사각형 버튼을 하나의 중성 표면에 묶습니다. 메뉴 버튼은 일반 조작 대비, 맨 위 이동은 primary 대비를 사용하며 흰 아이콘을 밝은 강조색 위에 직접 놓지 않습니다.
- 플로팅 조작부는 우측·하단 safe area를 포함해 최소 12px을 확보하고, sticky 행동·본문 라벨·브라우저 UI와 겹치지 않게 합니다. 열린 목록은 같은 표면 위에서 최대 48vh까지만 확장합니다.
- 상태 전환 120ms, 오버레이 180ms, 페이지 전환 240ms를 기준으로 하며 `prefers-reduced-motion`에서는 이동을 제거합니다.

## 어드민 반응형 계약

- 모바일 360–767px: 1열, 좌우 16px, 상단 메뉴, 주요 행동 2개, 전체 화면 오버레이.
- 모바일 상단 메뉴는 열리면 헤더 아래의 남은 뷰포트를 채우는 단일 열 패널로 표시합니다. 메뉴명은 줄임표로 자르지 않고 `번호 | 전체 라벨 | 현재 상태`를 같은 행에 두며, 그룹별 구분과 44px 이상의 터치 높이를 유지합니다. 2열 메뉴와 배경 페이지 스크롤은 금지하고 PDF·로그아웃은 패널 하단의 고정 행동 영역에 둡니다.
- 반응형 가이드의 모바일 표본은 실제 관리 페이지를 기본 상태로 보여주고, 상단 메뉴 버튼을 눌렀을 때만 전체 메뉴 상태로 전환합니다. 메뉴만 항상 펼쳐 둔 정적 표본은 페이지와 메뉴의 관계, 닫기 동작, 실제 작업 영역을 검증할 수 없으므로 사용하지 않습니다.
- 태블릿 768–1199px: 6열, 좌우 24px, 144px compact sidebar, 3·6열 필드, 화면 72% 드로어.
- 태블릿 내비게이션은 아이콘이나 번호만 노출하지 않고 메뉴명을 항상 표시합니다. 현재 메뉴명은 페이지 헤더에서도 온전히 반복합니다.
- 태블릿에서 폭이 부족한 경우 내비게이션을 더 줄이지 않고 데이터 표와 타임라인에만 가로 스크롤을 적용합니다.
- 모바일 표의 가로 스크롤은 기능은 유지하되 굵은 네이티브 스크롤바를 상시 노출하지 않습니다. 주변 안내 문구로 가로 이동 가능성을 설명합니다.
- 데스크톱 1200px 이상: 12열, 좌우 32px, 240px 사이드바, 최대 1440px 편집 영역, 최대 720px 드로어.
- 버튼 라벨은 줄바꿈하지 않고 값 영역은 말줄임보다 확장을 우선합니다.
- 중첩 입력은 화면 크기와 관계없이 한 레벨에 경계선 하나만 사용합니다.

## 방향

현재 기본 방문자 화면은 `Mist` 테마입니다. 목표는 장식적인 웹 카드 모음이 아니라 흰 종이에 정리된 포트폴리오 인쇄물에 가까운 화면입니다. 콘텐츠의 위계는 그림자나 과한 색보다 타이포그래피, 규칙선, 여백과 작은 기하학 표식으로 만듭니다.

## 색과 재질

- 기본 바탕은 따뜻함이 과하지 않은 흰색 계열입니다.
- 종이 질감은 매우 옅게 유지하며 콘텐츠를 방해하는 노이즈는 사용하지 않습니다.
- 본문은 짙은 중성색, 보조 정보는 낮은 대비의 회색을 사용합니다.
- 포인트 컬러는 한 화면에서 한 계열만 사용합니다.
- 히어로의 포그는 무채색이어야 하며 배경색을 붉게 물들이지 않습니다.
- 상위 제목, 소제목과 항목 제목은 동일한 다크 차콜을 사용합니다. 토프 색상은 섹션 라벨, 번호, 연도와 링크·현재 상태처럼 보조 정보 또는 행동을 나타낼 때만 사용합니다.
- 노란 프로젝트 면에서는 차가운 회색을 섞지 않습니다. 제목은 짙은 잉크, 본문은 중간 잉크, 메타·라벨은 낮은 대비의 올리브 브라운, 링크는 진한 올리브 브라운을 사용하며 모든 구분선은 같은 잉크색의 투명도 단계로 만듭니다.
- 구분선은 강한 섹션 경계, 일반 행 경계, 내부 보조선의 세 단계만 사용합니다. 같은 배경 안에서 회색과 갈색 선을 혼용하지 않습니다.

## 타이포그래피

- 한국어 본문은 Gowun Batang 계열을 중심으로 사용합니다.
- 제목은 인쇄물의 표제처럼 보이되 지나치게 장식적인 캘리그래피는 사용하지 않습니다.
- 모바일 주요 섹션 제목은 `clamp(2.15rem, 9.4vw, 2.4rem)` 범위로 통일합니다.
- 모바일의 읽는 본문은 15–16px, 보조 메타 정보는 12–13px를 기준으로 합니다.
- 성과 목록은 번호와 본문의 두 열 구조를 유지하되 제목은 18px, 설명은 16px로 표시합니다. 본문 속 수치 강조는 과한 굵기 대신 얇은 밑줄을 사용합니다.
- 본문 줄높이는 1.5–1.7 범위를 유지합니다.
- 어드민에 저장된 명시적 줄바꿈은 넓은 화면에서 우선 보존합니다. 모바일에서는 오버플로를 막기 위해 필요한 경우에만 추가 줄바꿈을 허용합니다.

## 레이아웃과 여백

- 섹션은 공통 종이 여백과 동일한 콘텐츠 폭을 사용합니다.
- 상단선과 하단선 사이의 콘텐츠는 시각적으로 중앙에 놓이도록 같은 세로 패딩을 사용합니다.
- 목록의 번호, 제목, 본문은 정해진 그리드 열에 맞춥니다.
- 모바일에서는 한 열로 전환하되 번호와 본문의 시작선을 섹션마다 임의로 바꾸지 않습니다.
- 데스크톱에서 충분한 너비가 있으면 의도하지 않은 제목 줄바꿈을 만들지 않습니다.

## 히어로

- 높이는 모바일 브라우저 UI 변화에 안전하도록 `100dvh` 기준을 사용합니다.
- `PORTFOLIO` 제목은 모바일 상단과 하단 콘텐츠 사이의 시각적 중심에 둡니다.
- 어드민의 태그라인과 헤드라인은 `PORTFOLIO` 가까이에 배치해 직무와 전문 영역이 첫 화면에서 바로 읽히게 합니다.
- 포그는 원 하나처럼 보이지 않는 구름형 무채색 블러로 천천히 움직입니다.
- 선명하게 열리는 중심 영역은 제한적으로 유지하며 배경 전체가 색 덩어리처럼 보이지 않게 합니다.
- 통계 행은 번호, 라벨, 연결선, 값을 동일한 수직 중심에 맞춥니다.

## 커리어 저니

- 각 행은 번호, 연도, 회사, 역할과 현재 상태를 고정된 그리드에 배치합니다.
- 현재 상태는 연도 바로 아래의 회전하는 반짝이 표식과 `NOW`를 함께 표시합니다.
- 현재 표식과 연도는 같은 그리드 열과 같은 좌측 시작선을 사용합니다.
- 행 전체는 해당 업무 경험으로 이동하는 버튼이므로 키보드 포커스 표시를 유지합니다.

## 프로젝트와 경력

- 프로젝트 카드 호버 시 크기와 위치가 움직이지 않습니다.
- 모바일 프로젝트는 각 사례의 제목, 설명, 단계, 지표와 결과 사이를 선과 여백으로 명확히 구분합니다.
- 모바일 프로젝트는 탭보다 먼저 최대 3개의 핵심 지표를 `At a glance` 요약으로 보여주고, Result 탭 안의 중복 지표는 숨깁니다.
- 움직이는 기하학 장식은 삭제하지 않으며 콘텐츠와 겹치지 않는 지정 위치를 사용합니다.
- 경력 항목의 본문과 `OTHER TASKS` 목록은 같은 본문 리듬을 사용합니다.
- 원본 프로젝트, 경력, 교육 및 활동 내용은 스타일 수정 때문에 삭제하거나 축약하지 않습니다.
- 교육과 외부 활동을 묶는 마지막 상위 섹션 제목은 간결한 `Background`를 사용하고, 내부 소제목에서 `Education`과 `Activities`를 구분합니다.

### 프로젝트 표현 방식

- 모든 항목은 같은 `프로젝트` 데이터 영역에 속합니다. 직무나 분야를 기준으로 `PM 프로젝트`, `디자인 프로젝트`처럼 고정 분류하지 않습니다.
- 현재 제공하는 표현 방식은 그룹·스토리·성과 중심의 `구조형`과 대표 이미지·상세 페이지·갤러리 중심의 `아카이브형`입니다.
- 표현 방식은 프로젝트의 직무나 성격이 아니라 화면에 보여주는 방법입니다. 이후 새 방식도 프로젝트 메뉴 안에 추가합니다.
- 기존 저장 키 `groups`, `designArchive`, `designProjects`와 업로드 경로는 데이터 호환을 위해 유지하되 사용자에게 보이는 정보 구조의 명칭으로 사용하지 않습니다.
- 메인은 최대한 선별된 추천 작업을 인덱스와 큰 대표 이미지로 보여줍니다.
- 모바일의 추천 작업 인덱스는 가로 스크롤 대신 한 열 세로 목록을 사용해 제목을 자르지 않습니다.
- 대표 이미지는 모바일, 아카이브와 상세 페이지에서 기본 3:2 비율을 유지하며 `object-fit: cover`로 표시합니다.
- 전체 아카이브 링크는 공개 프로젝트 수가 어드민의 노출 기준 이상일 때만 표시합니다.
- 상세 페이지는 `Problem → IA / User Flow → Design Solution → Validation → Design System` 순서를 기본으로 하되, 값이 없는 단계는 렌더링하지 않습니다.
- 상세의 Brief는 번호형 본문과 구분되는 옅은 종이 띠와 큰 도입 문장으로 표시합니다. 모바일에서는 한 열, 태블릿 이상에서는 라벨과 본문의 두 열 구조를 사용합니다.
- 상세의 닫기 동작은 원형 아이콘 대신 우측 상단의 `Close ×` 텍스트 링크로 유지해 메인으로 돌아가는 경로를 항상 노출합니다.
- 갤러리는 여러 이미지를 한 장씩 보여주며 이전·다음 버튼, 현재 순서와 썸네일 탐색을 제공합니다. 어드민에 저장한 이미지 순서가 프론트 노출 순서가 됩니다.
- 대표 이미지가 없을 때는 고정 비율의 `Image pending` 상태를 표시해 레이아웃 이동을 방지합니다.
- 이미지에는 의미 있는 대체 텍스트를 입력하고 장식 이미지에만 빈 대체 텍스트를 허용합니다.
- 아카이브형 프로젝트 제목과 본문은 모바일에서도 각각 46px 이상, 16px 이상을 기준으로 하며 메타 정보도 12px 미만으로 줄이지 않습니다.
- 모든 프로젝트 링크와 어드민 조작 버튼은 최소 44px 터치 영역을 유지합니다.
- 공통 푸터는 데스크톱에서 저작권·연락처·상단 이동의 세 열 시작선을 맞추고, 태블릿에서는 상단 이동을 우측에 둔 두 행, 모바일에서는 연락처·상단 이동·저작권 순서로 쌓습니다.

## 장식과 인터랙션

- 이모지는 사용하지 않습니다.
- 별, 점, 십자, 클로버 등은 CSS로 만든 단순 기하학 기호만 사용합니다.
- 장식은 의미 콘텐츠보다 낮은 시각적 우선순위를 가져야 합니다.
- 도형은 한 섹션의 한쪽 모서리에 몰아넣지 않고 페이지의 바깥 여백에 낮은 밀도로 분산합니다.
- 히어로 도형은 제목을 직접 가리지 않는 비대칭 위치로 구성하며, 모바일에서는 장식 수를 줄입니다.
- 호버는 색, 선 굵기 또는 미세한 텍스트 이동으로 표현하며 레이아웃을 흔들지 않습니다.
- 위치가 바뀌는 호버 효과는 `(hover: hover) and (pointer: fine)` 환경에서만 허용합니다. 터치 환경에서는 탭 후 남는 hover 상태가 텍스트 정렬을 바꾸지 않아야 합니다.
- `prefers-reduced-motion` 환경에서는 반복 이동과 진입 모션을 줄입니다.

## 반응형 점검 기준

- 모바일: 320px, 360px, 390px, 430px
- 태블릿: 768px, 1024px
- 데스크톱: 1280px, 1440px 이상

반응형 레이아웃은 세 구간으로 관리합니다. 모바일은 `0–767px`, 태블릿은 `768–1179px`, 데스크톱은 `1180px 이상`입니다. 모바일과 태블릿의 최종 여백·그리드 축소 규칙은 CSS의 `Mist responsive contract` 한 곳에서 관리하며 개별 컴포넌트에 중복 예외를 추가하지 않습니다.

- 모바일 섹션 상하 여백: 40px
- 태블릿 섹션 상하 여백: 56–68px
- 모바일 콘텐츠 좌우 여백: 20–24px
- 태블릿 콘텐츠 좌우 여백: 32–52px
- 1180px 미만에서는 업무 경험을 두 열 이하로 유지하고 상세 사례 본문은 한 줄 전체 폭을 사용합니다.

각 크기에서 다음을 확인합니다.

1. 가로 스크롤이 생기지 않는가
2. 제목이 충분한 공간에서도 불필요하게 줄바꿈되지 않는가
3. 본문이 15px 미만으로 작아지지 않는가
4. 섹션 시작선과 콘텐츠 시작선이 일관적인가
5. 규칙선이 이중으로 보이거나 중간에 끊기지 않는가
6. 장식이 본문과 겹치지 않는가
7. 포커스, 호버와 클릭 상태가 레이아웃을 움직이지 않는가

## 사이트 맵과 표시 계약

어드민 사이트 맵은 실제 관리 메뉴를 기준으로 유지합니다.

- 대시보드: 홈
- 콘텐츠: 프로젝트, 경력·학력, 소개, 핵심 성과, 커리어 저니
- 페이지 설정: 히어로, 접속 화면, 테마, 연락처
- 접속 관리: 토큰, 접속 로그
- 설정: 배지·스킬 분류, 변경 이력, 관리자 계정, 디자인 시스템

프론트의 공통 사이트 맵은 테마와 무관하게 다음 계약을 유지합니다.

- 인증 전에는 접속 화면에서 토큰의 유효성, 만료, 오류를 처리합니다.
- 홈 `/`은 히어로, 소개, 커리어 저니, 핵심 성과, 구조형 프로젝트, 경력·학력, 연락처를 표시합니다.
- 프로젝트 아카이브 `/projects`는 공개된 아카이브형 프로젝트 목록과 공통 연락처를 표시합니다.
- 프로젝트 상세 `/projects/:slug`는 대표 정보, 프로젝트 메타, 케이스 스터디, 갤러리, 이전·전체·다음 이동을 표시합니다.
- 케이스 스터디는 `Problem → IA / User Flow → Design Solution → Validation → Design System` 순서를 기본으로 하며 값이 없는 단계만 생략합니다.
- 테마는 색, 서체, 장식과 레이아웃 표현을 변경할 수 있지만 경로, 콘텐츠 계층, 공개 조건은 변경하지 않습니다.
- 배지·스킬 분류는 프로젝트의 배지 유형과 소개의 스킬 분류에 공통 허용값을 공급하며 독립 공개 페이지를 만들지 않습니다.
- 토큰은 접근 권한, 만료, 토큰별 테마를 제어하며 콘텐츠 원본을 변경하지 않습니다.

사이트 맵은 추상 도형이 아니라 실제 메뉴명, 공개 경로, 하위 콘텐츠와 `어드민 원본 → 공개 위치 → 표시 규칙` 표로 표현합니다. 라우트나 관리 메뉴가 바뀌면 구현과 이 문서를 같은 변경에서 갱신합니다.

## 사이트 식별 정보와 빌드 메타데이터

- 운영 도메인, 운영자 이름, 이메일 같은 사이트 식별 정보는 화면 코드에 직접 쓰지 않습니다.
- `VITE_SITE_URL`, `VITE_OWNER_NAME`, `VITE_OWNER_EMAIL`, `VITE_CONTACT_EMAIL`을 단일 입력으로 사용합니다.
- `index.html`, `robots.txt`, `sitemap.xml`의 URL과 이름은 빌드 시 같은 환경 변수로 치환합니다. 어드민 콘텐츠와 검색 엔진 메타데이터가 서로 다른 값을 가지지 않게 합니다.
- 운영 배포 후에는 샘플 이름, `your-domain` 같은 예시 도메인, `__SITE_URL__`·`__OWNER_NAME__` 같은 미치환 토큰이 결과물에 없는지 검사합니다.
- 브라우저 런타임의 URL 폴백은 로컬 개발용이며 운영 정본으로 사용하지 않습니다.

## 반복 금지 품질 게이트

- 광학 정렬은 박스의 상단 좌표가 아니라 첫 텍스트 베이스라인과 아이콘의 시각 중심으로 판단합니다.
- 번호·제목·설명·필드·액션은 공통 시작선을 공유하며 계단식 정렬을 허용하지 않습니다.
- 내용보다 큰 데모 프레임과 빈 상태는 센터 미들, 긴 편집 콘텐츠와 표는 상단 정렬합니다.
- 글자 크기는 역할 토큰만 사용합니다. 작은 메타는 작게 유지하되 공간 맞춤용 임의 크기는 만들지 않습니다.
- 세로로 긴 텍스트 버튼과 글자 단위 줄바꿈을 금지합니다. 아이콘 버튼은 정사각형을 유지합니다.
- 한 컴포넌트의 문제를 고친 뒤 같은 컴포넌트군, 모든 상태, Light·Dark, 360·768·1280px를 함께 확인합니다.
- 카탈로그에는 실제 컨트롤을 표시하고 select 화살표, 단일 포커스 선, 빈 상태·로딩·오류·복원까지 확인합니다.
- 어드민 폼의 열 전환은 브라우저 전체 폭이 아니라 내비게이션과 페이지 패딩을 제외한 실제 편집 폭을 기준으로 합니다. 태블릿에서는 1–2열, 충분한 데스크톱 편집 폭에서만 2–3열을 사용합니다.
- 높이가 다른 짧은 입력과 긴 설명 입력을 한 행에 억지로 맞추지 않습니다. 짧은 설정은 같은 행에 두고, 여러 줄 설명은 다음 행 전체 폭을 사용합니다.
- 모달과 드로어는 액션 바 내부가 아닌 문서 루트 포털에 렌더링합니다. sticky·filter·backdrop-filter에 의해 위치와 높이가 잘리지 않아야 합니다.
- 첫 방문과 로그인 화면의 기본 어드민 모드는 Light입니다. 사용자가 직접 고른 이후에는 저장된 Light/Dark 선택을 유지합니다.
- 공개 콘텐츠 편집 화면에서 테마를 다시 선택하거나 테마별 색상·현재 테마 안내·팔레트 견본을 중복 표시하지 않습니다. 테마 관리에서 저장한 팔레트는 별도 안내 없이 커리어 저니를 포함한 공개 화면 전체에 적용됩니다. 기존 항목의 과거 색상 값은 데이터 호환을 위해 보존하되 표시에는 사용하지 않습니다.
- 이 체크는 저장소 루트 `AGENTS.md`의 필수 작업 지침이며 이후 어드민 UI 변경 때마다 먼저 적용합니다.

## 변경 절차

시각 변경 후 `npm run check`를 실행합니다. 모바일과 데스크톱을 모두 확인한 뒤, 지속적으로 유지해야 할 규칙은 이 문서에 추가하고 사용자에게 보이는 변경은 `CHANGELOG.md`에 기록합니다.

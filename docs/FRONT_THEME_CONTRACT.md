# 공개 프론트 테마 계약

## 테마 디자인 시스템 진입 규칙

- 어드민의 각 테마 카드에 있는 `디자인 시스템 보기`는 선택 상태와 무관하게 해당 테마의 전용 가이드 파일을 새 탭으로 엽니다.
- Mist는 `/front-system.html`, 나머지 테마는 `/front-system-{theme}.html`과 1:1로 연결합니다. 다른 테마 파일로 대체하거나 공통 기본 파일로 우회하지 않습니다.
- 모든 테마 가이드는 동일한 공통 헤더 컴포넌트를 사용합니다. 제목·테마 전환·검토 종료의 위치, 44px 조작 높이, 활성 테마 표시는 동일하고 색만 현재 테마 토큰을 따릅니다.
- 헤더의 테마 버튼으로 다른 테마 가이드로 이동할 수 있습니다. `검토 종료`는 어드민에서 새 탭으로 연 경우 어드민 탭으로 돌아가며, 단독으로 연 경우 가이드 목록으로 이동합니다.

## 0. 적용 우선순위

새로 작성되거나 갱신된 이 계약과 해당 테마 가이드가 기존 CSS, 이전 화면, 과거 캡처, 오래된 컴포넌트보다 항상 우선한다. 서로 충돌하면 새 가이드를 예외 처리하거나 약화하지 않고 기존 구현을 수정한다. 어드민 디자인 시스템은 별도 범위이며 이 계약으로 변경하지 않는다.

Mist 테마의 상세 규칙은 [MIST_FRONT_SYSTEM.md](./MIST_FRONT_SYSTEM.md)에 있으며, 로컬 `front-system.html`과 같은 `src/mist-system-contract.js` 원문에서 생성한다. HTML과 Markdown에 규칙을 따로 복사해 편집하는 것을 금지한다.

이 문서는 공개 포트폴리오와 각 테마 가이드의 단일 기준이다. 어드민 UI는 범위 밖이며 `docs/DESIGN_SYSTEM.md`의 별도 계약을 따른다.

## 실제 서비스 적용 기준

- 검토된 Mist 가이드는 공통 스타일과 접근성 스타일 뒤에 로드되는 `src/mist-theme.css` 한 곳에서 실제 서비스에 적용한다.
- Mist 수정은 이 파일의 의미 기반 토큰을 사용하며 `src/index.css`에 임시 수치나 중복 덮어쓰기를 추가하지 않는다.
- `node scripts/audit-mist-front.mjs`로 360·390·430·768·1024·1440px, 모바일 진입 화면, 모바일 프로젝트 상세를 함께 검사한다.
- 공개 테마 적용 작업에서는 어드민 파일과 어드민 디자인 시스템 스타일을 수정하지 않는다.

## 1. 수정 순서

모든 수정은 아래 순서로 진행한다.

1. 콘텐츠 역할과 사용 맥락을 확인한다.
2. 테마의 핵심 은유, 정보 구조, 표면·선, 타이포그래피, 상호작용, 금지 요소를 분석한다.
3. 기존 공통 컴포넌트와 토큰으로 표현할 수 있는지 먼저 확인한다.
4. 새 요소는 해당 테마 분석에서 필요성이 증명될 때만 추가한다.
5. 동일 패턴을 사용하는 모든 테마와 모든 화면 크기를 함께 수정한다.
6. 자동 검수와 실제 화면 검수를 모두 통과한 뒤 완료한다.

## 2. 정렬 계약

### 공통 시작선

- 페이지는 문서화된 컨테이너와 열만 사용한다.
- 번호, 날짜, 제목, 본문, 입력, 액션은 역할별 고정 열을 공유한다.
- 정렬을 맞추기 위한 개별 `margin-left`, 음수 margin, 빈 요소 삽입을 금지한다.
- 그리드 열이 바뀌는 반응형 구간에서는 정보 순서를 유지하고 열만 재정의한다.
- 같은 정보 묶음의 섹션 표제, 그룹 헤더, 데이터 행은 하나의 열 정의를 공유한다. 그룹 라벨과 행 라벨, 그룹 설명과 행 제목의 시작선 오차는 1px 이하여야 하며 컴포넌트마다 별도 그리드를 만드는 것을 금지한다.

### 광학 정렬

- 박스의 `top`이나 CSS baseline만으로 합격 처리하지 않는다. 실제 글자 영역을 측정한다.
- 한 줄 행의 번호·메타·제목·상태 라벨은 실제 글자 중심 오차 1px 이하를 목표로 한다.
- 여러 줄 행은 번호·메타를 제목 첫 줄의 실제 글자 상단에 맞추며 오차는 2px 이하로 제한한다.
- 아이콘은 글자 line-box가 아니라 실제 대문자 높이의 시각 중심에 맞춘다.
- 서체별 보정은 컴포넌트 토큰으로만 관리한다. 요소마다 `top`, `translateY`, `padding-top`을 새로 만들지 않는다.
- 보정 토큰 이름은 역할을 드러낸다: `row-index-shift`, `section-index-shift`, `icon-optical-shift`.

### 날짜와 번호

- 날짜·연도·번호는 메타 정보다. 주제목 크기로 확대하지 않는다.
- 같은 역할의 날짜는 모든 문맥에서 같은 크기·굵기·line-box를 쓴다.
- 현재 상태는 연도 옆에 인라인으로 배치하고 행 높이를 늘리지 않는다.

## 3. 여백 계약

- 기본 간격 계열은 `4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96px`이다.
- 4px과 12px은 인라인·광학 보정, 20px은 표준 행 안쪽 여백에만 사용한다.
- 섹션 간격은 40px 이상, 콘텐츠 행은 16·20·24px 중 정의된 토큰만 사용한다.
- 행과 카드의 상하 padding은 같은 토큰을 사용하며 실제 차이는 1px 이하여야 한다.
- 고정 높이, 빈 줄, 불필요한 `<br>`, 상단 margin으로 수직 균형을 보정하지 않는다.
- 내용이 늘면 컨테이너가 자연스럽게 늘어나야 하며 하단 여백이 사라지지 않아야 한다.

## 4. 경계와 선택선

- 데이터 묶음은 첫 상단선과 마지막 하단선을 모두 소유한다.
- 인접한 두 컴포넌트가 같은 경계를 공유할 때 선은 한 번만 그린다.
- 섹션 제목의 선을 첫 데이터 행의 상단선으로 대신하지 않는다.
- 펼침 행의 요약은 제목과 같은 정보 묶음이므로 둘 사이에 구분선을 넣지 않는다. 구분선은 동급 행 사이 또는 `RESULT`처럼 의미가 바뀌는 하위 구획 앞에만 둔다.
- 펼침 제목과 첫 요약 사이 간격은 8px, 요약과 다음 하위 구획 사이 간격은 16px을 기본으로 하며 모든 업무 경험 프로젝트에 동일하게 적용한다.
- 마우스·터치 클릭 뒤에는 포커스 선을 남기지 않는다. 키보드 `focus-visible`에서만 테마별 단일 표시를 제공한다.
- outline, border, inset shadow가 동시에 보이는 이중 선택선을 금지한다.
- 탭의 현재 상태는 한 개의 밑줄로만 표시한다. 현재 탭이 키보드 포커스를 받아도 외곽선과 밑줄을 중첩하지 않는다.
- 선택형 인덱스 행은 좌측 상태선과 텍스트 사이에 최소 20px 안쪽 여백을 유지한다.
- 프로젝트 인덱스의 좌측 상태선은 `선택된 한 행`에만 지속 표시한다. 단순 hover에는 배경 면이나 상태선을 추가하지 않아 선택 상태와 혼동시키지 않는다.
- 프로젝트 인덱스는 모든 행에 `3px transparent border-left` 공간을 미리 예약하고 `aria-pressed="true"`인 행의 border 색만 바꾼다. 선택선을 shadow·outline·가상 요소로 다시 그리거나 focus가 선택선을 제거하게 두지 않는다.
- 이력서처럼 연속되는 장부 묶음은 앞 묶음의 마지막 하단선을 다음 묶음의 상단선으로 공유한다. 묶음 사이 빈 margin, 이중선, 강조선 혼용을 금지한다.
- Background의 Education·Activities 내부 경계는 전부 동일한 `1px rgba(41,40,36,.08)` 약선만 사용한다. 섹션 제목선, 그룹선, 데이터 행선에 서로 다른 굵기나 농도를 섞지 않는다.

## 5. 타이포그래피와 가독성

- 본문은 실제 프론트에서 15px 이상, 보조 정보는 12px 이상을 유지한다.
- 본문 행간은 140–160%, 한 줄 메타 line-box는 공통 토큰을 사용한다.
- 한글 타이틀은 별도 테마 명시가 없으면 Gowun Batang을 사용한다.
- 저장된 개행을 우선하되 공간이 부족할 때만 자연스럽게 줄바꿈한다.
- 데스크톱의 불필요한 두 줄 제목, 한글 낱글자 고립, 버튼 라벨 줄바꿈을 금지한다.
- 텍스트 대비는 WCAG AA 4.5:1 이상을 유지한다.
- 히어로 영문 표제는 데스크톱에서 120px을 넘지 않으며, 콘텐츠 폭의 92% 이내에서 한 줄을 유지한다.
- 프로젝트 Brief는 본문 역할이다. 데스크톱 17px, 모바일 16px의 본문 스케일을 사용하며 전시용 대형 인용문처럼 확대하지 않는다.
- 한글 본문과 프로젝트 설명은 `word-break: keep-all`과 읽기 폭 68ch 이하를 기본으로 하며 낱글자 고립이나 임의 `<br>` 삽입을 금지한다.
- 아카이브 소개는 제목 아래 같은 시작선에 두고 최대 68ch를 사용한다. 데스크톱에서 설명을 좁은 우측 열에 강제로 넣어 예방 가능한 줄바꿈을 만들지 않는다.
- About 본문은 원본 문장을 삭제하거나 임의 개행하지 않고, 데스크톱에서 최대 760px의 실제 읽기 폭을 사용한다. 이미지가 없는 상태에서 본문 열을 300px 안팎으로 축소해 여러 짧은 줄로 구기는 것을 금지한다.
- 프로젝트 요약은 데스크톱·태블릿에서 최대 78ch를 확보하고 균형 줄바꿈을 적용한다. 마지막 한두 어절만 다음 줄에 남는 고아 줄을 금지하며 CTA는 요약과 같은 시작선에 둔다.
- 프로젝트 Result는 어드민 Markdown의 명시 개행을 그대로 보존한다. 명시 개행이 없으면 데스크톱에서 전체 가용 폭을 먼저 제공해 좁은 내부 열 때문에 생기는 예방 가능한 줄바꿈을 금지한다.

## 6. 테마 분석과 격리

새 표현을 만들기 전에 각 테마를 다음 순서로 분석한다.

1. 핵심 은유: 무엇을 닮아야 하는가.
2. 정보 구조: 어떤 콘텐츠 관계를 강조하는가.
3. 표면과 선: 면, 경계, 그림자, 모서리의 역할은 무엇인가.
4. 타이포그래피: 제목, 본문, 메타의 역할과 대비는 무엇인가.
5. 상호작용: 전환이나 모션이 이해를 실제로 돕는가.
6. 금지 요소: 이 테마에 섞이면 정체성을 무너뜨리는 요소는 무엇인가.

공통 IA와 사용성은 유지하되 시각 문법은 테마별로 분리한다. Mist의 종이 질감, 포그, 반짝이, 랜덤 추종 커서는 Mist 밖에서 사용하지 않는다. 장식은 기본값이 아니며 기능적 이유가 없으면 추가하지 않는다.

### Mist 장식과 커서 안전영역

- 포그는 Mist의 핵심 표면 효과다. 표제를 덮는 흰 오브젝트가 아니라 글자와 종이 사이를 지나는 중립색 렌즈 블러로 구현한다.
- 3개 이상의 넓은 타원 마스크는 합집합으로 겹쳐 하나의 비정형 구름을 만든다. 불투명 중심에서 투명 가장자리까지 반지름의 60% 이상을 페더 구간으로 쓰며, 역마스크·`intersect` 합성·흰색 의사 요소를 금지한다.
- 포그가 지나간 글리프도 즉시 판독되어야 한다. 배경색 불투명도는 2% 이하, `backdrop-filter`는 데스크톱 3.2px·태블릿 2.6px·모바일 2.4px 이하로 제한하고 표제 자체의 opacity·filter는 바꾸지 않는다.
- 포그는 하나의 중앙 덩어리로 왕복하지 않는다. 최소 3개의 넓고 옅은 구름층이 서로 다른 주기(21~38초)로 히어로 가로 영역의 약 16~78%를 교차하며 순회하고, 세로 이동은 9% 이내로 제한한다. 글자 양끝을 잘라내거나 표제 전체를 동시에 가리는 경로를 금지한다.
- 포그를 단순 원형으로 축소하거나 표제 아래로 보내 사실상 보이지 않게 만드는 것을 금지한다. 모바일·태블릿에서도 같은 약한 블러 문법을 유지한다.
- 포그의 색은 종이색 계열만 사용하며 붉은색·채도가 있는 안개를 금지한다. `prefers-reduced-motion`에서는 포그를 제거하지 않고 정지 상태로 남긴다.
- 반짝이·점·십자·클로버는 제목, 라벨, 본문, 데이터 행의 실제 글자 영역과 최소 24px 떨어진 섹션 가장자리 안전영역에만 둔다.
- 장식은 카드나 행 중앙, 본문 종료 직후의 빈 공간에 임의로 놓지 않는다.
- 추종 커서의 목적 라벨은 포인터와 같은 글자 줄에 겹치지 않도록 포인터 아래로 분리한다.
- 추종 커서의 기본 랜덤 기호와 행동 요소의 목적 라벨은 동시에 표시하지 않는다. 링크·버튼에 진입하면 회전 기호를 숨기고 목적 라벨만 표시한다.
- 프로젝트와 업무 경험을 잇는 방향 기호는 실제 문서상 목적지 방향을 따른다. 위쪽 섹션으로 이동하면 `↖`, 새 페이지면 `↗`를 사용한다.

### 테마는 팔레트 교체가 아니다

- 테마 분석은 최소한 섹션 구성, 통계, 인덱스 행, 프로젝트 표현, 모션의 다섯 패턴에 연결되어야 한다.
- 같은 카드 그리드나 장부형 행을 그대로 둔 채 색·서체·radius·shadow만 바꾸는 구현은 불합격이다.
- 공통 컴포넌트는 의미, 정보 순서, 접근 가능한 이름, 터치 영역, 상태 모델만 공유한다. 보이는 구성은 각 테마가 소유한다.
- 페이지 전환과 스크롤 효과는 테마별로 검토하며 이해를 돕지 않으면 사용하지 않는다.
- 가이드 자체도 해당 테마의 타이포그래피, 표면 문법, 정렬, 컴포넌트 구성을 사용해야 한다. 중립 또는 Mist 파생 가이드 셸은 허용하지 않는다.

## 7. 반응형 계약

- 검수 폭: 320, 360, 390, 430, 768, 1024, 1280, 1440px.
- 모바일(`320-767px`)은 20px 좌우 여백의 엄격한 단일 열로 구성한다. 데스크톱 열을 좁혀서 유지하지 않는다.
- 태블릿(`768-1023px`)은 32px 좌우 여백을 사용한다. 짧은 메타 정보만 다열을 허용하고 경력·활동·긴 본문은 읽기 열로 접는다.
- 모바일 연속 섹션의 기본 블록 안쪽 여백은 48px이다. 인접 섹션의 데스크톱 여백을 중복 적용해 96px 이상의 공백을 만들지 않는다.
- 모바일 푸터는 메시지와 연락처를 먼저 묶고, 마지막 행의 저작권은 좌측, Back to top은 우측에 둔다. 링크와 라벨 내부 줄바꿈은 금지한다.
- 데스크톱 푸터의 좌측 저작권, 중앙 연락 묶음, 우측 Back to top은 같은 첫 줄 상단 기준선에 맞춘다. 중앙 묶음만 아래로 확장하며 다른 열을 하단 정렬하지 않는다.
- 390px 이상에서 푸터 안내 문장은 한 줄을 유지한다. 360px에서는 전체 가로 넘침을 만들지 않는 범위에서만 문장 한 번의 자연 줄바꿈을 허용하며 이메일·LinkedIn·Back to top 내부 줄바꿈은 금지한다.
- 모바일 프로젝트 상세 breadcrumb는 `Portfolio / Design archive`까지만 표시한다. 현재 프로젝트 제목은 히어로에만 두어 고정 Close와 충돌하지 않게 한다.
- 모바일에서 본문을 삭제하거나 극단적으로 축소하지 않는다.
- 모든 터치 대상은 44×44px 이상이다.
- 전체 페이지 가로 오버플로는 금지한다. 갤러리처럼 필요한 영역만 내부 스크롤을 허용한다.
- 태블릿은 데스크톱 축소판이 아니다. 열 수와 시작선을 명시적으로 재정의한다.
- 선택적 이미지가 로드되지 않으면 이미지 열 자체를 제거한다. 빈 고정 열이나 대체 여백을 남기지 않는다.
- 기본 샘플 프로젝트의 커버 경로·대체 문구·위치는 `sampleContent`의 실제 프로젝트 데이터로 보유하고, 기존 저장본의 같은 샘플 ID·slug·제목에 이미지 필드가 비면 데이터 마이그레이션 단계에서 복원한다. 컴포넌트나 테마 CSS에 샘플별 경로·이름을 하드코딩하는 것을 금지한다.
- 모든 테마는 동일한 `coverImage`, `coverAlt`, `coverPosition`, `coverMode`, `gallery` 데이터 계약만 읽는다. 이미지 로딩 실패는 실제 `<img>` 오류 상태로 감지하고 빈 배경으로 위장하지 않는다.
- 아카이브와 상세 페이지는 모두 우측 상단에 44px 이상의 `Close` 이탈 경로를 제공하며 메인 포트폴리오로 복귀한다.
- 메인에 `#home`이 없는 아카이브·상세 페이지도 60vh 이상 스크롤하면 플로팅 Top을 제공하고, 공통 푸터가 보일 때는 숨긴다.
- 플로팅 Top은 의미 없는 순번이나 장식 값을 넣지 않고 `Top ↑`만 광학 중앙 정렬한다. hover·pressed에서도 위치와 크기를 바꾸지 않는다.
- 디자인 아카이브는 데스크톱·태블릿 2열, 모바일 1열의 동일 폭 카드 그리드를 사용한다. nth-child 기반 엇갈린 span·상단 들여쓰기로 빈 열이나 화면 이탈을 만들지 않는다.
- 상세 Meta의 하단선과 바로 이어지는 Brief의 상단선은 같은 경계이므로 한 번만 그린다. Brief는 별도 회색 박스가 아니며 투명 종이 면과 14% 잉크 약선만 사용한다.
- 서브페이지 첫 콘텐츠의 상단 여백은 데스크톱 최대 80px, 모바일 40px을 넘지 않는다.
- 접근 화면은 데스크톱에서 소개 묶음과 인증 폼의 상단을 맞추고, 두 열 사이 간격은 64px을 넘기지 않는다. 태블릿·모바일에서는 두 묶음을 순서대로 쌓는다.

## 8. 상호작용과 상태

- hover·focus·pressed는 색, 선, 농도만 바꾼다. 위치, 크기, padding, 글자 정렬을 바꾸지 않는다.
- Loading, Empty, Error, Access Expiring, Expired, Restored 상태는 제목, 원인, 다음 행동을 제공한다.
- 접속 만료 10분 전부터 남은 시간과 다음 행동을 비차단 경고로 알린다. 경고는 보호 콘텐츠를 밀어내거나 레이아웃 높이를 바꾸지 않는다.
- 접속 만료 시 보호 콘텐츠를 즉시 언마운트하고, 뒤 콘텐츠가 비치지 않는 불투명한 전체 화면 재인증 게이트로 교체한다. 백그라운드 탭은 focus·pageshow·visibilitychange 시 만료를 즉시 재검사한다.
- `prefers-reduced-motion`에서는 반복 모션과 장식 전환을 제거한다.
- 통계 장부는 `번호 40px / 라벨 유동 / 값 최소 48px` 열을 유지하며 번호가 라벨 위로 겹치지 않아야 한다.

## 9. 자동 합격 기준

- 모든 검수 폭에서 페이지 전체 가로 오버플로 0.
- 한 줄 텍스트 군 실제 중심 편차 1px 이하.
- 여러 줄 행 첫 글자 상단 편차 2px 이하.
- 행·카드 실제 상하 padding 편차 1px 이하.
- 첫 상단선과 마지막 하단선 존재, 이중 경계 0.
- 프로젝트 인덱스의 지속 선택선은 정확히 1개이며 hover·mouse focus 뒤에도 임의 행으로 이동하거나 사라지지 않는다.
- focus-visible 표시 1개, 44px 미만 터치 대상 0.
- 모든 테마에서 Home, Product Case, Career, Background, Design Archive, Project Detail, Access Gate를 검수한다.
- 자동 수치 검수와 별개로 390, 430, 768, 1024px 전체 페이지 캡처를 직접 판독한다. 가로 오버플로가 0이어도 정보 위계, 과도한 공백, 부자연스러운 줄바꿈 중 하나가 보이면 실패다.
- 프로젝트 섹션은 모든 검수 폭에서 `섹션 제목 → 그룹 헤더 → 프로젝트 행`의 열 시작선과 제목-첫 목록 간격 16–36px을 자동 측정한다.
- 가이드 화면도 동일 기준을 통과해야 한다.
- 만료 시각을 지난 화면에서 보호 콘텐츠 DOM이 남아 있거나 재인증 게이트 뒤로 읽히면 배포 실패다.
